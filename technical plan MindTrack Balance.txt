Технічний план MindTrack Balance:
1) Цінність та обсяг продукту
Мета: допомогти користувачу керувати балансом “емоції ↔ увага” через щоденні короткі записи, аналітику й м’які інтервенції (затримки/фокус-режими), з перспективою соціальної підтримки (групи/чати) та добровільного самоконтролю (блокування доменів/апок).
Версії:
MVP (Web + розширення браузера + PWA): трекінг настрою/тексту, базова аналітика, лічильники часу в соцмережах, “паузи-тертя”, щотижневий звіт, білінг.
Після MVP: React Native (iOS/Android), голосові нотатки, розширені правила фокусу/блокування, “Сократ-режим” (активне мислення), групи підтримки, сімейний/командний режим.
2) Архітектура (запас на майбутнє)
Підхід: модульна, подієво-орієнтована система зі слабким зв’язком між компонентами.
Frontend Web (Next.js 15, App Router, PWA)
UI-shell + модулі: Mood, Attention, Advice, Reports, Settings, Billing.
Browser Extension (MV3)
Легка логіка перехоплення доменів, локальна телеметрія, опційна синхронізація з бекендом.
Mobile App (React Native) — після валідації MVP
Ті ж доменні модулі; спільна API-контрактна схема.
Backend (NestJS)
Сервіси: Auth, Entries, Attention, Analytics, Advice, Rules, Reports, Billing, Social(пізніше).
Data: PostgreSQL (OLTP) + S3-сумісне сховище для експортів/медіа; (пізніше) ClickHouse/BigQuery для аналітики.
Черги/фон: Redis + BullMQ (аналіз тексту, побудова звітів, емейли/push).
AI-шар: абстракція LLMProvider (OpenAI/локальні), NLPService (тональність/теми) — через інтерфейс, щоб легко міняти провайдера.
Події: EventBus (внутрішні доменні події: EntryCreated, AttentionEventLogged, ReportReady), для реактивних фіч.
Feature Flags: ConfigCat/Unleash — включати майбутні модулі без релізу нових версій.

Примітки для розширення:
– AttentionRule дозволяє з часом додати батьківський/груповий контроль (через owner_id/політики).
– Group*/Post готують ґрунт для міні-спільнот.
– Consent — явні згоди, щоб змінювати політики без переробки БД.

5) MVP Web — вимоги та backlog
Функціонал MVP
Щоденний запис
Mood(1–5) + 140 символів.
AI-аналіз (тон/теми) у фоні.
Історія + фільтри за темами.
PWA: офлайн-кеш, синх при онлайні.
Відстеження уваги
Розширення MV3: перехоплення відкриття tiktok|instagram|youtube|facebook|reddit (список з Settings).
5–10 сек “затримка” із кнопкою “обійти” + лог події.
Збір метрик локально; за згодою — синх у бекенд.
Дашборд
Графік настрою (лінія), хвилини/день (стовпчики), простий інсайт: зв’язок у % між днями з >Х хв скролу й середнім настроєм.
Щотижневий звіт
Автогенерація неділя 19:00 (таймзона профілю).
Емейл + у додатку: 3 інсайти, 1–2 поради.
Білінг (Freemium → Pro)
Stripe Checkout + Customer Portal.
Free: 30-денна історія, 1 правило “затримки”, базові графіки.
Pro: повна історія, кілька правил, PDF-звіт, розширені інсайти.
Приватність
Явні Consent.
Видалення акаунта (GDPR-style).
Експорт даних (JSON/CSV).
Нефункціональні
Латентність UI: <150–200 мс на збереження Entry.
Надійність фон-джоб: при падінні процесу черга відновлює задачі.
Облік квот LLM: захист від надмірних витрат.
i18n: uk/en з day-1.
Observability: HTTP-логування, трасування ключових потоків (sign-in, create entry, gen report), метрики черг.
Backlog (скорочено, 20 задач)
FE: EntryForm, EntryList, Dashboard, Settings, Reports, Billing pages, PWA (service worker).
BE: entries.service, attention.service, nlp.worker, reports.worker, billing.webhooks.
EXT: onBeforeNavigate + DelayOverlay, локальний Storage, батч-синхронізація.
QA: unit на nlp.mapper, інтеграційні на entries, e2e “create-analyze-report”.
6) Після MVP — еволюція без переробок
A) React Native (4–6 тижнів)
Екрани 1:1 з Web.
Нативні push’і (ранок/вечір/тижневий).
Голосові нотатки → локальна транскрипція (за можливості) або серверна; зберігання як Attachment.
Вбудований WebView з “м’яким фокус-режимом” для популярних сайтів.
B) Розширені правила уваги
AttentionRule.kind=limit|window|block + windows[] (cron-подібні).
“Focus Mode” (добровільне замикання на N часу) + відкладене відкриття.
Сімейний/наставницький доступ (агреговані метрики, без контенту).
C) “Сократ-режим” (активне мислення)
Перед відповіддю AI користувач пише коротку власну версію → AI порівнює та дає підсвітки, не “готове рішення”.
Облік як Advice + мікро-квести.
D) Групи підтримки
Group, GroupMember, Post (анонімні ніки).
Реакції “підтримати” замість лайків.
Soft AI-модерація токсичних патернів.
Челенджі 7/14 днів (серії, бейджі).
E) Аналітика/Дані
Перенесення агрегацій у ClickHouse/BigQuery для звітів без навантаження на Postgres.
Паблік-дашборд анонімної статистики.
7) Безпека, приватність, етика
Data-minimization: збираємо лише події/час/домени/апки — без вмісту сторінок.
Opt-in: відстеження уваги та синхронізація — лише за згодою.
Reversible controls: будь-яке блокування/затримка вимикається користувачем (зарезервовано для батьківського режиму з окремою згодою).
Видимість для груп/сім’ї: лише агрегати (хвилини, серії), нуль приватних текстів.
Шифрування: у спокої (PGP-ат-rest/SSE-S3), у транзиті (TLS), ключі в Secret Manager.
Логи: без PII у прод-логах.
8) Тестування та реліз
Unit: мапери NLP, обчислення інсайтів, правила уваги.
Integration: API entries, attention, Stripe-webhook.
E2E (Playwright): створення запису → аналітика → звіт → білінг.
Extension QA: сценарії “блок”, “затримка”, “обхід”, збій мережі, повторна синхронізація.
Canary-релізи через feature flags, поступове вмикання розширених правил.
9) Монетизація (вбудовано в технічну реалізацію)
План Free/Pro/Duo/Teams у Subscription.
Квоти LLM/аудіо в Quota; сторінка upsell при вичерпанні.
Stripe Customer Portal для самостійного керування підпискою.
In-app покупки для “мікро-квестів” (контент-паки).
10) UX-орієнтири (щоб уникнути переробок)
Design tokens (кольори/шрифти/spacing) у одному місці; тема світла/темна з day-1.
Form schemas через Zod — одна схема і для FE, і для BE (типобезпечність).
Компонентний підхід: графіки/картки/модалки як бібліотека.
Інструментальні пороги: усе, що може бути параметром (поріг хвилин, довжина затримки, список доменів), — у Rules, а не в коді.
Підсумок
MVP концентрується на трьох ядрах: записи емоцій, базова аналітика “емоції ↔ увага”, м’які інтервенції (затримки) + щотижневий звіт і білінг.
Архітектура одразу готує місце під мобільний застосунок, розширені правила фокусу, групи підтримки, голосові нотатки, Сократ-режим — без ламання контрактів/схеми даних.
Усе критично чутливе (AI-провайдер, аналітика, правила) — зашито через інтерфейси, фічефлаги і таблиці конфігурацій, тож майбутні зміни не потребуватимуть переписування.

- mindtrack (сервіс MindTrack)
Записи настрою, аналітика, поради, звіти, підписка + квоти, outbox для подій.
// schema.prisma (mindtrack)
model Entry {
id String @id @default(uuid())

model EntryNlp {

- attention (сервіс Attention)
Івенти з розширення/мобіли й правила “затримка/ліміт/вікна/блок”.
// schema.prisma (attention)
enum EventSource { EXTENSION MOBILE }
enum TargetType { DOMAIN APP }
enum EventAction { OPEN BYPASS BLOCKED }
model AttentionEvent {
id String @id @default(uuid())
userId String @index
ts DateTime @default(now())
source EventSource
targetType TargetType
targetId String // youtube.com або com.tiktok.app
action EventAction
durationSec Int? // якщо відомо
}
enum RuleKind { DELAY LIMIT WINDOW BLOCK }
model AttentionRule {
id String @id @default(uuid())
userId String @index
kind RuleKind
targetType TargetType
targetId String // шаблон домену/апки
params Json // {seconds, quotaPerDay, windows: [{from,to}], …}
enabled Boolean @default(true)
createdAt DateTime @default(now())
}
model RuleUsage {
id String @id @default(uuid())
ruleId String @index
userId String @index
ts DateTime @default(now())
matched Boolean @default(true)
bypassed Boolean @default(false)
}

Ролі та доступ
JWT з role і plan приходить із твого auth.
Продукт: role = "user" — весь звичайний функціонал.
Адмінка: тільки role = "superadmin" (allowlist емейлів/IDs на бекенді).
Немає жодних ендпоінтів, що повертають контент користувача в адмінку.
